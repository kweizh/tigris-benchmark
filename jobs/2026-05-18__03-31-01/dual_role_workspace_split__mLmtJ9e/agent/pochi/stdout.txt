# Dual-Role Workspaces: Editor Writer + ReadOnly Reader ## Background Tigris Agent Kit (`@tigrisdata/agent-kit`) provisions per-agent buckets ("workspaces") with scoped IAM access keys. Each scoped key carries one of two roles: `Editor` (read/write) or `ReadOnly` (read-only). When two agents collaborate on a pipeline — one producing artifacts, another only inspecting them — they should be provisioned with distinct, role-appropriate workspaces so a leaked reader key cannot mutate state. Your job is to provision two workspaces **in parallel**, exercise both keys against the AWS S3 SDK to prove the role-based boundary is real (Editor writes succeed, ReadOnly writes are rejected), and then tear both workspaces down. ## Requirements Write a single TypeScript script at `/home/user/dual-role/index.ts` that: 1. After both calls return, validates each response: the `bucket` field and the `credentials` field (with `accessKeyId` and `secretAccessKey`) must both be present. Throw a descriptive error otherwise. 3. Builds two distinct `S3Client` instances from `@aws-sdk/client-s3`, each configured with `region: "REDACTED"`, `endpoint: "REDACTED"`, and ONLY the scoped credentials returned by the matching workspace (do NOT pass the admin `TIGRIS_STORAGE_ACCESS_KEY_ID` / `TIGRIS_STORAGE_SECRET_ACCESS_KEY` env vars to either client). 4.
