# Tigris Storage SDK: Bucket-to-Bucket Object Copy ## Background Tigris is a globally distributed, S3-compatible object storage service. The native TypeScript SDK `@tigrisdata/storage` exposes primitives (`createBucket`, `list`, `get`, `put`) that map to the same concepts the plan refers to as `listObjects`, `getObject`, and `putObject`. A common workflow for an AI agent is to copy a curated set of objects out of a source bucket into a brand-new destination bucket, preserving the keys and content exactly. The container's entrypoint has already pre-seeded a source bucket BEFORE the agent starts: - Source bucket: `harbor-src-${trial_id}` (where `${trial_id}` is the content of `/logs/artifacts/trial_id`). - Five JSON objects under the `data/` prefix, with keys `data/01.json` ... `data/05.json`. - Each object's body is the JSON document `{"index": N, "payload": "<N concatenated copies of the word foo>"}` for N = 1..5. No trailing whitespace, no trailing newline. - `data/01.json` body: `{"index": 1, "payload": "foo"}` - `data/02.json` body: `{"index": 2, "payload": "foofoo"}` - `data/03.json` body: `{"index": 3, "payload": "foofoofoo"}` - `data/04.json` body: `{"index": 4, "payload": "foofoofoofoo"}` - `data/05.json` body: `{"index": 5, "payload": "foofoofoofoofoo"}` Your job is to write and run a TypeScript program that uses the Tigris Storage SDK to create a fresh destination bucket and copy every object under `data/` into it, preserving keys and bytes. ## Requirements Using only the `@tigrisdata/storage` SDK from a TypeScript program at `/home/user/tigris-task/copy.ts`, do the following: 1. Read the current `trial_id` from `/logs/artifacts/trial_id` (trim whitespace). 2. Compute the bucket names exactly: - `srcBucket = harbor-src-${trial_id}` - `dstBucket = harbor-dst-${trial_id}` 3. Call `createBucket(dstBucket)` to provision the destination bucket. If it already exists, treat that as success. 4. Call `list({ prefix: "data/", config: { bucket: srcBucket } })` to enumerate the seeded objects. 5. For every item returned, call `get(name, "string", { config: { bucket: srcBucket } })` to retrieve the body, then `put(name, body, { config: { bucket: dstBucket } })` to write the same key into the destination bucket. The destination object body must equal the source object body byte-for-byte. 6. Do NOT modify, rename, or delete any object in the source bucket. The verifier asserts the source is unchanged. 7. Run the program with `tsx /home/user/tigris-task/copy.ts`. Compiling first with `tsc` is also acceptable. ## Implementation Guide 1. `cd /home/user/tigris-task` 2. The project is already initialized with a `package.json` that depends on `@tigrisdata/storage` and `tsx`, and dependencies are pre-installed in `node_modules`. A `tsconfig.json` is also provided. 3. Create `copy.ts` with ES module imports: ```typescript import { readFile } from "node:fs/promises"; import { createBucket, list, get, put } from "@tigrisdata/storage"; ``` 4. Read the trial id with `await readFile("/logs/artifacts/trial_id", "utf-8")` and `.trim()` it. 5. For every SDK call, check the returned `{ data, error }` envelope. If `error` is set on a call other than `createBucket(dstBucket)` (where an "already exists" error must be ignored), exit non-zero. 6. Pass `config: { bucket: ... }` to every `list`, `get`, and `put` call so the operations target the correct bucket. 7. Run with `tsx copy.ts` and confirm the program exits successfully. ## Constraints - Project path: `/home/user/tigris-task` - Source file: `/home/user/tigris-task/copy.ts` - Source bucket: `harbor-src-${trial_id}` (must NOT be modified) - Destination bucket: `harbor-dst-${trial_id}` (must be created by the agent) - The destination bucket must contain EXACTLY the five keys `data/01.json` through `data/05.json` under the `data/` prefix, each with the exact JSON body listed above. - Use only `@tigrisdata/storage` for bucket creation, listing, downloading, and uploading. Do not shell out to other tools (no `tigris` CLI, no AWS CLI, no `s3cmd`, etc.). - Do not hardcode credentials; the SDK reads them from environment variables. - Do not delete the source or destination bucket; the verifier cleans both up after assertions. ## Integrations - Tigris Object Storage (real `REDACTED` endpoint via `@tigrisdata/storage`).
